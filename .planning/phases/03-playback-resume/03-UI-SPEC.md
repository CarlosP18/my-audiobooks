# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope reminder:** Phases 1-2 shipped an installable, data-driven library screen with import and swipe-to-delete. This phase adds exactly one new screen — a dedicated player route (`/player/[id]`, D-01) — with full transport controls (play/pause, ±15s skip, scrub-to-seek) and live elapsed/remaining time (PLAY-01–06). **All colors, spacing, and typography below are inherited verbatim from `01-UI-SPEC.md`/`02-UI-SPEC.md`/`app/globals.css` — nothing is reinvented.** This is the first phase where Geist Mono actually renders on screen (reserved for this since Phase 1) and the first phase to hand-vendor `@radix-ui/react-slider` (flagged `[SUS]`/"too-new" in `03-RESEARCH.md`'s Package Legitimacy Audit — that is a separate npm supply-chain gate the planner must insert as `checkpoint:human-verify` before `pnpm add`; it is **not** a third-party UI registry and does not require this document's registry-content-vetting gate, since it is the same shadcn/Radix family already twice-approved in this project). Background/lock-screen playback (Media Session API) is explicitly out of this phase's visual scope (PLAY2-02, v2) — this screen only needs to work correctly in the foreground.

## Layout — Player Screen (`/player/[id]`)

**Source:** `03-CONTEXT.md` D-01 (dedicated route), D-02 (5s save throttle), D-03 (scrub pause-on-drag/seek-on-release), D-04 (end-of-book terminal state); `03-RESEARCH.md` Architecture Patterns 1-4 and Pattern 3's Radix Slider callback split.

Root container: `min-h-dvh`, flex column, Dominant background (`#0A0A0A`) — matches the library screen. Top safe-area inset is already handled globally by `app/layout.tsx`'s body padding; this screen additionally needs bottom safe-area clearance for the home indicator (transport controls sit near the bottom of a full-height flex layout, unlike the library list which is top-anchored). Per STATE.md's Phase 2 blocker note that Tailwind arbitrary-value classes (`pb-[calc(...)]`, `bottom-[env(...)]`) rendered unreliably on a physical iPhone PWA, apply bottom safe-area padding as an **inline style**, not an arbitrary Tailwind class: `style={{ paddingBottom: "max(24px, env(safe-area-inset-bottom))" }}` on the root container.

Top to bottom:

1. **Header row** — `lg` (24px) horizontal padding, `xl` (32px) top padding, matching the library screen's header rhythm exactly. Contains only a back button, left-aligned: `ChevronLeft` icon (lucide, 24px, Foreground `#F5F5F5`), `aria-label="Back to library"`, `min-h-11 min-w-11` (44×44px) tap target via padding, navigates to `/` via `next/link` `Link href="/"` (not `router.back()` — deterministic regardless of how the player route was entered, including a deep link or PWA relaunch). No page title duplicated in the header; the book title renders large below (see 3).

2. **Artwork placeholder** — `2xl` (48px) top margin below the header. A centered square, `Secondary` background (`#171717`), rounded `8px` (matching row/dialog rounding elsewhere in the app), max width `240px` (responsive: `min(240px, 100% - 2 × lg)`), `aspect-square`. Centered inside it: the `BookAudio` icon (lucide, 96px, Muted-foreground `#A3A3A3`) — the same glyph already used for the library empty state, reused here as a deliberate visual echo rather than a new icon choice. This is a placeholder for real cover art (deferred to v2, META-01) built entirely from already-locked tokens — no new asset, no external design tool, consistent with Phase 1 D-02's "no external design tools" constraint.

3. **Book title** — `xl` (32px) top margin below the artwork. Heading typography (20px/600/1.2), Foreground (`#F5F5F5`), centered, `lg` (24px) horizontal padding. **Overflow:** `line-clamp-2` (max 2 lines, CSS ellipsis on the second line) — filename-derived titles (LIBR-03) can be long and are not developer-controlled; full title available via the container's `aria-label`. This is the same overflow risk `02-UI-SPEC.md` already identified for library-row titles, just at a larger size and 2-line allowance instead of 1-line truncation (there is vertical room here that the library row didn't have).

4. **Scrub bar + time readout** — `2xl` (48px) top margin below the title, `lg` (24px) horizontal padding.
   - **Scrub bar:** hand-vendored `@radix-ui/react-slider` (`Slider.Root`/`Track`/`Range`/`Thumb`), full width. `min={0}`, `max={book.duration}`, `step={1}`, controlled `value={[dragValue ?? position]}` per D-03/Pattern 3 in `03-RESEARCH.md`. Track height 4px, rounded-full, track color `#171717` (Secondary — identical unfilled-track color to the existing `Progress` component for visual consistency between the library row and the player). Filled range color: Accent `#E8B34A` (this is the "active progress-bar fill" Phase 1's Color section explicitly reserved Accent for). Thumb: 20px diameter circle, Accent `#E8B34A` fill, no border — visually a continuation of the filled range, not a separate control. Radix's `Root` captures pointer events across the full track width (not just the thumb), so no extra touch-target padding is required beyond the track's own hit area; the executor should still confirm on a physical device that dragging near the thumb feels precise (`03-RESEARCH.md` Assumption A1, flagged for on-device verification).
     - `onValueChange` (continuous, during drag): pause audio on the first move of a drag (remembering prior play/pause state), update only the displayed thumb position/time — never call `audio.currentTime` here (D-03).
     - `onValueCommit` (once, on release): set `audio.currentTime` to the committed value; resume playback if it was playing before the drag began. Per `03-RESEARCH.md` Pitfall C, this resume-`.play()` call is a second iOS gesture-unlock-sensitive call site — the plan must include a named on-device test for "scrub while playing, release" (not just the primary play button). If it fails on-device, the approved fallback is: leave the book paused after a scrub, requiring a second explicit tap on the play button — this is a real (if minor) UX regression from D-03's implied "seek and continue," but it is the documented fallback, not an undefined failure state.
   - **Time readout:** `sm` (8px) top margin below the scrub bar, flex row, `justify-between`. Both values render in **Geist Mono** (`font-mono`), Label typography (14px/400/1.5), Muted-foreground (`#A3A3A3`) — the first on-screen use of the Mono font reservation. **Format — locked to mirror `formatTimeRemaining()`'s exact word-based phrasing/minute-granularity style (not raw `mm:ss` clock digits)**, for direct visual/verbal consistency with the library row (`03-CONTEXT.md` canonical_refs explicitly calls for staying consistent with Phase 2 D-06's format) and to avoid a jittery once-per-second digit tick:
     - Left (elapsed): a new, symmetric `formatElapsed(secondsElapsed)` helper in `lib/format.ts`, mirroring `formatTimeRemaining()`'s exact rounding rule (round to whole minutes **before** branching on the hour boundary — same reasoning as the code comment already in `formatTimeRemaining()`) but with "elapsed" wording: `< 60s` → `"<1m elapsed"`; `< 60min` → `"{m}m elapsed"`; `>= 60min` → `"{h}h {m}m elapsed"`.
     - Right (remaining): reuse `formatTimeRemaining()` as-is — already returns `"{m}m remaining"` / `"{h}h {m}m remaining"` / `"<1m remaining"`.
     - Both values recompute on a throttled UI tick during `timeupdate` (independent of D-02's separate 5s **database**-write throttle — the visible text should update roughly once per second for a live feel, per the Architecture Diagram's "update visible elapsed/remaining text (throttled UI, not just writes)" note; exact UI-tick interval is an implementation detail, not a locked design decision).
     - Example, a 5.5-hour book 20 minutes in: left = `"20m elapsed"`, right = `"5h 10m remaining"`.

5. **Transport controls** — `2xl` (48px) top margin below the time readout, flex row, `justify-center`, `items-center`, `lg` (24px) gap between the three controls.
   - **Skip back 15s** (left): `44×44px` tap target (`min-h-11 min-w-11`), `RotateCcw` icon (lucide, 28px, Foreground `#F5F5F5`) with a `"15"` numeral composited on top — `absolute inset-0 flex items-center justify-center`, Geist Mono, 10px, weight 700 (bold — the one deliberate exception to the app's 400/600 weight lock, scoped narrowly to this icon-overlay numeral, matching the well-established "skip 15" podcast-icon convention), Foreground color, nudged `pt-[3px]` to sit inside `RotateCcw`'s open arc. `aria-label="Skip back 15 seconds"`. Tapping calls `audio.currentTime = Math.max(audio.currentTime - 15, 0)` (PLAY-02) — always enabled, clamps silently at 0 rather than disabling near the start (Claude's Discretion item in `03-CONTEXT.md`, resolved here: no disabled-button visual state exists for this control in this phase).
   - **Play/Pause** (center): 72×72px circle, Accent `#E8B34A` background — this is the exact control Phase 1's Color section reserved Accent for ("the Phase 3 play/pause button"). Icon: `Play` (paused state) or `Pause` (playing state), 32px, color `#0A0A0A` (Dominant, dark) — **not** Foreground white. Computed contrast of `#0A0A0A` icon on `#E8B34A` fill ≈ 10.4:1 (WCAG AAA for both text and graphical contrast); white `#F5F5F5` on the same amber would only reach ≈1.8:1, which is why the icon uses the dark token instead of the app's usual Foreground color. `aria-label="Play"` / `"Pause"` toggles with state. Tap handler is synchronous — `audio.play()`/`audio.pause()` called with no intervening `await`, per `03-RESEARCH.md` Pattern 2 (iOS gesture-unlock requirement, PITFALLS.md Pitfall 3).
   - **Skip forward 15s** (right): mirrors skip-back exactly — `RotateCw` icon + `"15"` numeral overlay, same sizing/color/typography, `aria-label="Skip forward 15 seconds"`. Tapping calls `audio.currentTime = Math.min(audio.currentTime + 15, book.duration)` (PLAY-02) — clamps at `duration` without pushing past the D-04 end-of-book state, always enabled (same no-disabled-state resolution as skip-back).
   - **End-of-book note (D-04):** when the `ended` event fires, `position` is set to `duration` and playback stops; the Play/Pause button reverts to its `Play` icon (not disabled, not hidden). If the user taps Play again from this exact terminal state, `audio.currentTime` is already at `duration` and playback will immediately re-fire `ended` with no audible output — this phase does not design a special "restart" affordance for that tap; the user can scrub backward via the scrub bar to relisten to any earlier portion, which is the expected recovery path.

**Loading state** (initial `useLiveQuery(() => db.books.get(id))` read, before first resolve): render only the header (back button), identical in spirit to the library screen's `books === undefined` loading pattern (`02-UI-SPEC.md`) — no spinner, no flash of the not-found or populated state.

**Not-found state** (`useLiveQuery` resolves to `undefined` *after* the loading state has settled — a deleted book, LIBR-05, or a stale/malformed `[id]`): render the header (back button still works) plus a centered block matching the library empty-state's visual rhythm (`flex-1 items-center justify-center`, `sm` (8px) gap): Heading "Book not found" (Foreground), Body "This audiobook may have been deleted. Go back to your library." (Muted-foreground), and a text link "Back to Library" — Body typography, Accent `#E8B34A` color (the one place besides play/pause and the active fill that Accent is used, because it is functionally the primary action available in this dead-end state), navigating to `/`. A malformed (non-numeric) `[id]` route param is treated identically to a not-found book — no separate "invalid id" copy (`03-RESEARCH.md` Security Domain V5: both outcomes are the same to the user).
