## Icon & Splash Direction

**Source:** D-02 (code-generated book + audio-wave glyph, single solid color, no external design tools), D-03 (dark neutral black/graphite theme), PITFALLS.md Pitfall 1 (iOS ignores `manifest.json` icons — requires a separate, opaque `apple-touch-icon`).

- **Glyph concept:** a single flat-color glyph combining a simplified open-book silhouette with 3-4 vertical audio-wave bars (inspired by lucide's `book-open` + `audio-lines` forms, but drawn as one custom merged SVG path — not a literal icon-on-a-square composite). No gradients, no photographic/textured elements, no drop shadows.
- **Generation method:** generate programmatically via Next.js App Router's native icon conventions — `app/icon.tsx` using `ImageResponse` (from `next/og`) for the manifest-referenced PWA sizes (192×192, 512×512), and a separately rendered `app/apple-icon.tsx` (or a pre-rendered static PNG committed to `public/apple-touch-icon.png`) sized exactly **180×180px with a fully opaque background — no transparency**. iOS renders transparent pixels as black; the background fill must be a real solid color, not `transparent`.
- **Color:** glyph foreground = near-white `#F5F5F5` (Foreground token, see Color section) on a solid graphite/black background fill = `#171717` (Secondary token). This keeps the home-screen icon visually consistent with the in-app dark-neutral theme rather than introducing a third, icon-only color.
- **Safe area:** keep the glyph within a centered ~70% safe area of the canvas — iOS applies its own corner-radius mask on top, so nothing load-bearing should sit within ~15% of any edge.
- **Manifest wiring:** `app/manifest.ts` `icons` array covers 192×192 and 512×512 (`purpose: "any"`, plus a `"maskable"` variant using the same safe-area rule). Root layout `<head>` metadata must additionally declare `<link rel="apple-touch-icon" href="/apple-touch-icon.png">` explicitly — the manifest array alone is not sufficient on iOS (PITFALLS.md Pitfall 1).
- **Splash/theme color:** `app/manifest.ts`'s `background_color` and `theme_color` both set to the Dominant token `#0A0A0A`. Root layout metadata also sets `<meta name="theme-color" content="#0A0A0A">` and `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">` for full dark-bleed status bar styling, paired with `<meta name="viewport" content="viewport-fit=cover">` and explicit `env(safe-area-inset-top)` padding on the root layout container so content never renders under the translucent status bar.

## Layout — "My Library" Screen (Empty State)

**Source:** D-04 (final empty-library layout, not a placeholder — page title "My Library", empty list area, "No audiobooks yet" empty state). This is the only screen this phase ships.

- **Root container:** full-viewport height (`min-h-dvh`), flex column, Dominant background (`#0A0A0A`), `env(safe-area-inset-top)` padding at the top (see status-bar note above).
- **Header:** page title "My Library" — Display typography token, left-aligned, `lg` (24px) horizontal padding, `xl` (32px) top padding.
- **Empty-state block:** centered both axes in the remaining space below the header (`flex-1`, `items-center`, `justify-center`, no Card/border chrome — plain centered text, matching the minimalist direction). Vertical stack, `sm` (8px) gap between elements:
  1. Muted glyph mark (the book+wave icon at ~64px, Muted-foreground color, decorative/low-opacity) — optional visual anchor, not required for correctness.
  2. Empty-state heading: "No audiobooks yet" — Heading typography token, Foreground color (`#F5F5F5`).
  3. Empty-state body: "Import an audiobook to start listening." — Body typography token, Muted-foreground color (`#A3A3A3`).
- **No primary CTA button renders in Phase 1** (see Copywriting Contract — import doesn't exist until Phase 2/IMPT-01). The body copy is forward-looking guidance text, not a broken affordance — it names no specific on-screen control.
- **Offline load:** per D-05, no special offline banner/indicator — the shell renders identically online or offline (airplane mode), since nothing on this screen depends on the network.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0A` | Page background, splash screen background, `theme-color` |
| Secondary (30%) | `#171717` | Elevated surfaces reserved for future use (Phase 2 library rows/cards, icon background fill) — not visibly distinct from Dominant anywhere in Phase 1's UI itself |
| Accent (10%) | `#E8B34A` (warm amber) | Reserved exclusively for: primary interactive controls — the Phase 3 play/pause button, active progress-bar fill, and the single primary CTA button introduced in Phase 2 (Import). **Not present anywhere in Phase 1's rendered UI** — declared now so Phase 3 inherits a locked token instead of inventing one. |
| Destructive | `#DC2626` (red-600) | Reserved for the Phase 2 delete-book confirmation action only. Not present in Phase 1. |

Additional foreground tokens (not in the 60/30/10 split, needed for text legibility on the dark surfaces above):

| Token | Value | Usage |
|-------|-------|-------|
| Foreground | `#F5F5F5` | Primary text (page title, empty-state heading, icon glyph color) |
| Muted-foreground | `#A3A3A3` | Secondary/supporting text (empty-state body copy, decorative glyph mark) |

Accent reserved for: Phase 3 play/pause control, Phase 3 active progress-bar fill, Phase 2 primary Import CTA button. Never used for body text, backgrounds, or decorative elements in Phase 1.
