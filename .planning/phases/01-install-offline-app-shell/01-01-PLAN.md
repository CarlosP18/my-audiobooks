<objective>
Ship the branded, installable, standalone app shell for My Audiobooks — the walking skeleton for the whole project.

**User story (MVP):** **As a** person who wants his audiobooks on his phone, **I want to** add My Audiobooks to my iPhone home screen and open it like a real app, **so that** it feels like an app I own rather than a web page I have to go find in Safari.

This plan scaffolds the repo per D-06 (Next.js App Router + Tailwind + shadcn/ui) and D-07 (pnpm), renders the final "My Library" empty-library screen per D-04, generates the book-and-audio-wave glyph per D-02 in the dark-neutral palette per D-03, names the app "My Audiobooks" per D-01, and wires every iOS-specific manifest and meta tag that INST-01 (install to home screen) and INST-02 (standalone launch) depend on. Per D-05 nothing on this screen depends on the network, so it renders identically online and offline once Plan 02 adds the service worker.

Purpose: this is the riskiest platform assumption in the project. If iOS will not install this app with a correct icon and launch it without browser chrome, Phase 2 and Phase 3 have nothing to build on. Proving it on real hardware first is the whole point of the phase.
Output: a running Next.js app, the complete PWA metadata surface, three generated icon sizes, the locked design-token system every later phase inherits, and a repeatable installability gate.
</objective>

Wire ONE path from an empty repo through every layer this phase touches — build toolchain, route render, design tokens, web manifest, and iOS icon metadata — so that a browser hitting `/` gets a fully installable page. No second screen, no components, no extra routes.

**Step 1 — scaffold.** From the repo root, run `create-next-app` non-interactively with pnpm (D-07) selecting TypeScript, ESLint, Tailwind CSS, App Router, Turbopack, no `src/` directory, and the `@/*` import alias. Preserve the existing `.planning/` and `.claude/` directories — if the scaffolder refuses to write into a non-empty directory, scaffold into a temporary sibling directory and move the generated files in, never the reverse.

**Step 2 — shadcn init.** Run the shadcn CLI's init command via `pnpm dlx` (do NOT add `shadcn` as a project dependency). Configure it to write `components.json` with exactly: `style` = `new-york`, `baseColor` = `neutral`, `cssVariables` = `true`, `tsx` = `true`, `iconLibrary` = `lucide`. This is the structural preset from the sibling `neoancestral` project (D-06). Add **zero** components — Phase 1's screen is pure Tailwind typography and layout; init exists only so Phase 2 (Button, Card) and Phase 3 (Slider) can add components later without reconfiguring. Do NOT copy `neoancestral`'s color tokens or fonts; this project's palette is defined in Step 3.

**Step 3 — design tokens in `app/globals.css`.** Run this AFTER shadcn init, because init rewrites `globals.css`. Next 16 ships Tailwind v4 CSS-first configuration, so tokens live in `globals.css` (via `@theme` / CSS custom properties) and there is NO `tailwind.config.ts` — do not create one. Declare all six locked colors from UI-SPEC.md Color: Dominant `#0A0A0A`, Secondary `#171717`, Foreground `#F5F5F5`, Muted-foreground `#A3A3A3`, Accent `#E8B34A`, Destructive `#DC2626`. Accent and Destructive are declared now so Phase 2's Import CTA and Phase 3's play control inherit locked tokens instead of inventing them; neither is referenced by any Phase 1 markup. Also declare the four typography roles (Label 14px/400/1.5, Body 16px/400/1.5, Heading 20px/600/1.2, Display 28px/600/1.2) and the seven spacing steps (4, 8, 16, 24, 32, 48, 64 px). Only two font weights exist in this system: 400 and 600. Set the page background to the Dominant color.

**Step 4 — `app/icon-glyph.tsx`.** Export a single `IconGlyph` component taking a pixel size and returning the JSX that `ImageResponse` renders: a solid `#171717` square filling the canvas, centring one flat `#F5F5F5` mark that merges a simplified open-book silhouette with three or four vertical audio-wave bars (D-02 — minimalist, single solid color, no gradient, no photographic element, no drop shadow, drawn as one merged SVG path rather than two icons pasted together). Constrain the mark to a centred safe area of roughly 70% of the canvas: iOS applies its own corner-radius mask, so nothing load-bearing may sit within about 15% of any edge. The background must be that plain hex fill and nothing else — no alpha-channel color function, no see-through fill — because iOS renders any non-opaque icon pixel as pure black, which is exactly the "broken icon" failure mode PITFALLS.md Pitfall 1 describes. One glyph module, consumed by all three sizes, so the home-screen icon and the manifest icons can never drift apart.

**Step 5 — `app/apple-icon.tsx`.** Next's `apple-icon` file convention. Export `size` = `{ width: 180, height: 180 }`, `contentType` = `image/png`, and a default function returning `new ImageResponse(<IconGlyph size={180} />, { ...size })`. Exactly 180 by 180 — this is the only icon iOS reads for Add to Home Screen, and Next auto-emits the corresponding link tag into the document head from this file's existence. Getting this file wrong is the difference between a branded app and a pixelated screenshot on the user's home screen.

**Step 6 — `app/pwa-icon/route.tsx`.** A GET route handler reading a `size` search param, accepting only `192` and `512` and responding 400 for anything else, returning `new ImageResponse(<IconGlyph size={n} />, { width: n, height: n })` with `content-type: image/png`. These serve the manifest's icon array. They are spec-compliance and future-proofing — iOS ignores manifest icons entirely — so they must be correct but they are not what makes the iPhone install work.

**Step 7 — `app/manifest.ts`.** Default-export a function returning `MetadataRoute.Manifest` with `name` and `short_name` both `My Audiobooks` (D-01), `start_url` `/`, `display` `standalone` (INST-02 depends on this literal value), `background_color` and `theme_color` both `#0A0A0A` (D-03 — this is the splash-screen fill), and an `icons` array with three entries: 192x192 `purpose: any` and 512x512 `purpose: any` and 512x512 `purpose: maskable`, each `type: image/png`, each `src` pointing at the `pwa-icon` route with the matching size query. Next serves this at `/manifest.webmanifest` and links it automatically.

**Step 8 — `app/layout.tsx`.** Export `metadata: Metadata` with `title` `My Audiobooks` and an `appleWebApp` block setting `capable: true`, `statusBarStyle: 'black-translucent'`, `title: 'My Audiobooks'`. Export `viewport: Viewport` with `themeColor: '#0A0A0A'` and `viewportFit: 'cover'`. These two exports are what emit `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `theme-color`, and `viewport-fit=cover` — all four are required together, and PITFALLS.md Pitfall 1 documents that a missing capability tag is the usual cause of an "installed" app that still shows Safari's address bar. Wire Geist Sans and Geist Mono through `next/font/google`, which downloads and self-hosts the font files at build time so the served page fetches nothing from an external host at runtime. Wire both fonts even though Phase 1 renders only Geist Sans — Geist Mono is reserved for Phase 3's timecode display, and wiring it now means Phase 3 never touches font config. Apply the Dominant background and `min-h-dvh` to the body, and apply `env(safe-area-inset-top)` padding to the root container so content never renders under the translucent status bar. `viewport-fit=cover` and the safe-area inset are a matched pair: declaring one without the other leaves content either clipped or floating.

**Step 9 — `app/page.tsx`.** The final empty-library layout per D-04 — this is the screen Phase 2 fills in, not a placeholder that Phase 2 discards. Flex column, full viewport height. Header: the page title `My Library` at the Display role (28px / 600 / 1.2), left-aligned, 24px horizontal padding, 32px top padding. Below it a `flex-1` region centred on both axes with an 8px gap and no card, border, or surface chrome, containing: an optional decorative glyph mark at about 64px in the Muted-foreground color, then the heading `No audiobooks yet` at the Heading role (20px / 600 / 1.2) in Foreground `#F5F5F5`, then the body `Import an audiobook to start listening.` at the Body role (16px / 400 / 1.5) in Muted-foreground `#A3A3A3`. Both strings are locked verbatim by the Copywriting Contract. Phase 1 renders no interactive control of any kind — the Import affordance arrives in Phase 2 with IMPT-01, and the body copy is deliberately worded as forward-looking guidance that names no on-screen control, so it stays accurate until then. Per D-05 there is no offline banner, no connectivity indicator, and no install-instruction UI: the shell renders identically online and offline because nothing on it depends on the network.
