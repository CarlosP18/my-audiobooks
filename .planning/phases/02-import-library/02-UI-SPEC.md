## Layout — "My Library" Screen (Data-Driven)

**Source:** `02-CONTEXT.md` D-01–D-08, `02-RESEARCH.md` Architecture Patterns (Pattern 2: `useLiveQuery()`).

- **Root container:** unchanged from Phase 1 — full-viewport height (`min-h-dvh`), flex column, Dominant background (`#0A0A0A`), `env(safe-area-inset-top)` padding at top.
- **Header:** page title "My Library" (Display token, unchanged) stays left-aligned. **New this phase:** once the library has at least one book, a header-level import trigger renders top-right — a `Plus`-icon-only button (24px icon, Accent color `#E8B34A`, `aria-label="Import audiobook"`, min 44×44px tap target via padding, no visible border/background). This is a scope-filling decision, not a contradiction of D-01: D-01 only specifies the trigger for the *empty* state (the empty-state body copy becomes tappable, no button is added *there*); once the list is populated, the empty-state copy no longer renders, so a header entry point is required for the user to import additional books. This also fulfills Phase 1's original Accent reservation ("single primary CTA button introduced in Phase 2 (Import)").
- **Empty state (0 books):** unchanged from Phase 1's locked layout — centered glyph + "No audiobooks yet" heading + "Import an audiobook to start listening." body copy. **New this phase:** the body copy text itself becomes the tap target (D-01) — wrapped in a `<button>` element for correct semantics/accessibility, but with **zero visual change** (same Muted-foreground color, same Body typography, no underline, no color shift) to stay faithful to D-01's "no separate button or icon is added." Invisible padding extends the button's hit area to a minimum 44×44px touch target (spacing exception, see below) without altering the visible text's size or position. Tapping opens the iOS file picker.
- **Populated state (1+ books, including the transient placeholder row):** list of rows below the header, `md` (16px) horizontal padding matching header, `sm` (8px) vertical gap between rows, single-column vertical stack, no virtualization (personal-library scale per `02-RESEARCH.md` Pitfall 5 rationale).
- **Loading state (initial `useLiveQuery()` read, before first resolve):** render nothing but the header and root background — no spinner, no flash of empty state. `books === undefined` → return only the header (per `02-RESEARCH.md` Pattern 2). This is near-instantaneous for IndexedDB reads at this scale, so no dedicated loading UI is designed beyond "don't flash the wrong state."

## Import Flow — Placeholder Row (D-02)

**Decision:** the placeholder row shows an **indeterminate spinner**, not a percentage progress bar. Rationale: the actual copy operation is a single atomic `db.books.add()` call (per `02-RESEARCH.md` Pattern 3 — no chunked writes, no byte-level progress events available); showing a fabricated percentage would misrepresent real progress. This is distinct from — and must not be visually confused with — the *populated*-row progress bar (LIBR-04), which shows real, meaningful playback-position data once a book exists.

- **Container:** identical Secondary-surface (`#171717`) row shape/dimensions as a populated library row, so the row does not visually jump when it resolves into the real book.
- **Title:** the cleaned title (D-04/D-05) renders immediately — title cleanup is a synchronous string transform on the filename and does not depend on the async duration read, so there's no reason to withhold it.
- **Status line (replaces the progress bar + percent/time-remaining line):** `LoaderCircle` spinner icon (16px, Accent color `#E8B34A`, spin animation) + Label-typography text "Importing…" in Muted-foreground color, inline, `xs` (4px) gap between spinner and text.
- **Interaction:** the placeholder row does not respond to swipe-to-delete — the book doesn't exist as a stored record yet, so there is nothing to delete mid-write. No visual affordance suggests it's swipeable.
- **Resolution:** once `db.books.add()` succeeds, `useLiveQuery()` re-renders and this row's `key` is replaced by the real populated row (same position in the list, ordered by `importedAt`).

## Import Failure — Inline Error Banner (D-03)

**Placement:** directly below the import trigger (below the header's `Plus` button when populated; below the empty-state body copy when empty) and above the library list. Does not block or overlay the rest of the screen (D-03: "no full-screen error state").

**Visual treatment:** Secondary-surface (`#171717`) banner, `md` (16px) padding, rounded corners matching library rows. **Deliberately does not use the Destructive color** — Destructive (`#DC2626`) is reserved exclusively for the delete action in this phase (per `01-UI-SPEC.md`'s explicit reservation and this phase's scope reminder); reusing it for a non-destructive informational error would break that lock. Instead:
- Message text: Body typography, Foreground color (`#F5F5F5`).
- Dismiss control: a small `X` (lucide, 16px, Muted-foreground color) top-right of the banner, min 44×44px tap target via padding, `aria-label="Dismiss error"`.
- Banner auto-clears when the user successfully imports a file afterward, or can be manually dismissed; it does not auto-timeout (errors about storage/format need to stay visible until acknowledged).

**Copy (three variants, covering every failure path named in D-03 and `02-RESEARCH.md`'s Pitfalls 1/2/4, plus the duration-read failure resolved below):**

| Failure case | Copy |
|---|---|
| Unsupported format (extension not in `.mp3`/`.m4a`/`.m4b`) | `Couldn't import "{filename}" — only MP3, M4A, and M4B files are supported.` |
| Insufficient storage (`QuotaExceededError` or `AbortError` on write) | `Not enough storage to import "{filename}".` |
| Duration unreadable / corrupted file (hidden `<audio>` `error` event) | `Couldn't import "{filename}" — the file may be corrupted or unsupported.` |
| Any other copy error | `Couldn't import "{filename}". Try again.` |

**Duration-read-failure resolution (closes `02-RESEARCH.md` Open Question 1 from a UI-contract standpoint):** if the hidden `<audio>` element's `error` event fires instead of `loadedmetadata`, treat this exactly like a failed import (third row above) — do **not** write a partial/degraded book record with an unknown duration. This keeps every row in the library guaranteed to have a valid, playable duration, eliminating an ambiguous "partial" state the library-row UI would otherwise need to handle.

**Multi-select:** the file picker allows multiple selection (`<input type="file" ... multiple>`, per `02-RESEARCH.md`'s diagram). Each selected file runs the full pipeline (placeholder row → success or its own error) independently — a failure on one file does not block or roll back the others. Multiple error banners do not stack; if a new failure occurs while a banner is already showing, the banner's message is replaced with the newest failure (no queue, no counter — keeps the UI simple for what is expected to be an occasional, single-file-at-a-time personal action).

## Library Row — Populated State (LIBR-01, LIBR-03, LIBR-04)

- **Container:** Secondary surface (`#171717`), rounded (`8px` matching Phase 1's general rounding conventions), `md` (16px) padding, min-height 44px (touch/swipe target), full width minus `md` (16px) horizontal screen padding.
- **Title:** cleaned title (D-04/D-05) — Body typography (16px/400/1.5), Foreground color (`#F5F5F5`). **Overflow:** single-line, `truncate` (CSS ellipsis), never wraps — filename-derived titles can be long and are not developer-controlled. Full title available to assistive tech via the row's `aria-label`.
- **Progress bar:** shadcn `Progress` component, 4px height, full row width, `sm` (8px) margin above/below, track color Dominant-on-Secondary (subtle, near-invisible unfilled track), fill color Accent (`#E8B34A`). Value = `Math.round((position / duration) * 100)` — always `0` for every book in Phase 2 (position only advances in Phase 3), so every row's bar renders at 0% fill in this phase, which is correct and expected, not a bug.
- **Percent / time-remaining line:** Label typography (14px/400/1.5), Muted-foreground color (`#A3A3A3`), directly below the progress bar. **Format (D-06 — both together, always):** `"{percent}% — {timeRemaining} remaining"`.
  - Percent: `Math.round(position/duration*100)` + `"%"` (always `"0%"` in Phase 2).
  - Time remaining, derived from `duration - position` in seconds:
    - `>= 3600s`: `"{h}h {m}m remaining"` (e.g., `"2h 15m remaining"`, minutes rounded to nearest whole minute)
    - `>= 60s and < 3600s`: `"{m}m remaining"` (e.g., `"45m remaining"`)
    - `< 60s`: `"<1m remaining"`
  - Full example for a freshly imported 5.5-hour book: `"0% — 5h 30m remaining"`.
- **Swipe-to-delete (D-07):** swiping the row left reveals a full-height Destructive-colored (`#DC2626`) action panel behind it, right-aligned, containing a `Trash2` icon (Foreground/white, 20px) and "Delete" label (Label typography, Foreground color). Matches native iOS list-swipe conventions — no permanently-visible delete icon in the row's resting state. Tapping the revealed action opens the confirmation dialog below; swiping back right or tapping elsewhere dismisses the revealed action without deleting.

## Delete Confirmation Dialog (LIBR-05, D-07, D-08)

- **Component:** shadcn `alert-dialog` (Radix-based) — chosen over `window.confirm()` specifically because the native browser dialog cannot be styled to match the locked dark-neutral tokens (per `02-RESEARCH.md`'s Alternatives Considered).
- **Trigger:** the "Delete" action revealed by the swipe gesture (not a separate always-visible icon).
- **Visual:** dialog surface uses Secondary color (`#171717`) on the Dominant backdrop (dimmed overlay), Heading typography for the title, Body typography for the description.
- **Title:** `"Delete book"`
- **Description (locked verbatim, D-08 — no paraphrasing):** `"Delete book: Remove '{title}' and free its storage? This can't be undone."` — `{title}` is the book's cleaned display title, not the raw filename.
- **Actions:** `Cancel` (default/neutral button, Secondary-surface styling, no accent) and `Delete` (Destructive-colored `#DC2626` background, Foreground/white text) — Destructive is used here and only here in this phase, per the locked reservation.
- **On confirm:** `db.books.delete(id)` removes both the Blob and metadata record in one call (single co-located table per `02-RESEARCH.md` Pattern 1); the row disappears from the list immediately via `useLiveQuery()`'s automatic re-render — no manual refetch, no optimistic-UI flicker needed since Dexie's delete + live query round-trip is expected to be effectively instant at this data scale.
- **On cancel:** dialog closes, swipe-revealed action panel resets to hidden, nothing is deleted.
